# Cliploom 使用说明

Cliploom（把视频织成知识，把文案变成作品）是一款免费的 Windows 本地软件，用来下载或导入视频、抓取微信读书中的公众号文章、将语音转成文字，并让 Codex、Claude 或其他 AI 通过 MCP/API 读取文案和写回分析结果。

软件不需要登录、激活、订阅或购买额度。视频、文案、任务记录和 AI 分析默认都保存在本机。

## 关于我和《蓝皮书》

我是数字生命卡兹克，长期关注人工智能、技术产品和内容创作，也持续把日常阅读、实践和判断沉淀为可以复用的知识。

《蓝皮书》是这套长期积累的内容与方法记录：它不是一份只在发布时更新的资料，而是一套会随着新文章、新案例和真实实践不断补充的个人知识底稿。它关注的不只是“发生了什么”，也关注问题背后的结构、证据、方法和下一步行动。

Cliploom 是为这套工作方式做的本地工作台：把视频、公众号文章、文案、Markdown 创作稿和 AI 分析放进同一条可追溯的工作流里。抓取只是开始，真正的目标是让素材能够被保存、理解、整理、引用，并最终变成自己的知识和作品。

```text
多平台视频链接 / 抖音博主主页 / 本地文件
                ↓
          下载或导入视频
                ↓
        Faster-Whisper 转写
                ↓
    微信读书公众号文章归档
                 ↓
        外部 AI 读取和分析
                ↓
         分析结果写回软件
```

> 本仓库同时支持源码开发版和 Windows x64 安装包。安装包目标为 Windows 10/11；安装包不包含现有视频、数据库、配置文件或 Whisper 模型。

## 1. 五分钟快速上手

### 第一步：启动软件

如果使用安装包，双击 `Cliploom-1.1.0-setup.exe` 安装后，从开始菜单或桌面快捷方式启动即可。安装包版不需要 Node.js、Python 或项目目录。

如果使用源码开发版，进入项目目录，双击：

```text
启动视频文案工作台.bat
```

启动脚本会同时启动桌面界面、下载服务和内容服务。请保留随软件出现的命令行窗口；关闭它会结束开发版软件。

旧的 `启动抖音下载.bat` 和 `启动前后端(开发联调).bat` 也会转到同一个视频文案工作台。

### 第二步：完成首次设置

打开左侧“设置”，依次确认：

1. 新安装默认使用 `Documents\Cliploom` 内容库；如需兼容旧目录，软件会优先建立无损目录联接，不会复制或删除已有视频。
2. 如有需要，再点击“选择目录”自定义视频、TXT 和 SRT 的保存位置。
3. 保持“自动转写”开启，下载或导入完成后会自动排队转写。
4. 根据需要设置是否保留水印。
5. Whisper 模型建议选择 `medium`，设备建议选择“自动”。
6. 点击“保存全部设置”。

工作台会优先复用项目目录 `models/<模型名>` 中已经准备好的模型，其次复用当前用户的 Hugging Face 本机缓存。开发版运行环境使用项目根目录 `.venv`，不再依赖项目外的 `transcribe` 目录。

### 第三步：添加视频

最简单的方式是在“视频库”上方粘贴一个或多个视频链接，或者直接粘贴平台分享出来的整段文字。系统会自动提取其中的 HTTP/HTTPS 视频地址：

1. 每行粘贴一个链接。
2. 勾选“我拥有版权或已获得授权”。
3. 点击“加入工作台”。

下载完成后，该视频会立即进入转写队列，不需要等其他视频全部下载完。

### 第四步：查看文案

在视频库中点击一条视频，然后在右侧点击“文案”：

- 可查看当前文案和历史转写版本。
- 可复制全文。
- 可打开视频、TXT、SRT 或其所在文件夹；文本文件优先在软件的文本窗口中查看。
- 等待中的任务可点击“优先转写”。
- 已停止或失败的任务可重新开始。

### 第五步：让 AI 分析文案

打开左侧“接口中心”：

1. 确认显示“本地服务运行中”。
2. 点击“复制完整配置”。
3. 将配置添加到支持 Streamable HTTP MCP 的 AI 客户端。
4. 让 AI 列出待分析视频、读取文案并将分析写回。
5. 回到视频右侧的“AI 分析”页签查看结果。

可以直接对 AI 说：

> 请使用视频文案工作台，列出文案已就绪但尚未分析的视频。选择一条读取完整文案，从总结、开头钩子、结构、目标受众、亮点、问题和优化建议几个方面分析，并将 Markdown 结果写回工作台。

### 可选：抓取微信读书公众号文章

在“文章库”中可以把微信读书收藏的公众号文章保存为本地 Markdown 和历史快照，作为知识库和创作参考：

1. 打开左侧“文章库”，点击“登录微信读书”，使用微信扫描二维码并在手机确认。登录凭据只保存在本机。
2. 在文章库左栏输入完整公众号名称并添加。添加后点击该公众号行右侧的同步按钮，开始抓取。
3. 第一次同步按“每轮抓取数量”执行，默认目标为 20 篇新增文章；已经抓过的文章会跳过，但不占用本轮新增额度。软件会继续翻页，直到达到本轮新增目标、历史结束或遇到需要处理的问题，不会只固定查看最新 20 条。
4. 同步结果会显示发现、新增、跳过、快照和需关注数量。已有文章不会因为同步失败、重启或重新打开软件而删除。
5. 如果公众号过去的游标不正确，点击该公众号行的“从头”，确认后会把游标重置到历史第一页，再按同样规则重新扫描；已存在的文章会去重，不会重复创建。

微信读书可能要求官方客户端完成人工验证。Cliploom 会弹出验证提示：打开微信读书，进入“书架”的“文章收藏”，点击公众号名称而不是文章标题，完成验证后回到 Cliploom 点击“验证完成，立即抓取”。验证失败时已有文章和历史快照仍会保留。

文章自动补齐需要在顶部勾选“自动补齐”，设置同步间隔和每轮新增数量，然后只在需要补齐的公众号行勾选“自动”。多个公众号不会同时抓取：自动队列一次只执行一个公众号，完成或失败后才轮到下一个，降低触发平台风控的风险。自动同步失败会保留进度并在下一轮重试，也可以从提示框中手动重试。

## 2. 界面说明

软件采用三栏工作台布局：

| 区域 | 作用 |
| --- | --- |
| 左栏 | 切换视频库、主页抓取、批量转写、接口中心和设置 |
| 中栏 | 搜索、筛选、勾选及批量管理全部视频 |
| 右栏 | 查看当前视频的概览、文案版本和 AI 分析历史 |

左侧功能：

- **视频库**：查看和管理全部视频资产。
- **文章库**：登录微信读书、添加公众号、同步公众号文章和历史快照。
- **主页抓取**：获取一个抖音博主主页中的多个视频。
- **批量转写**：选择电脑中的文件或文件夹，扫描后批量转写。
- **接口中心**：查看 MCP/API 地址和访问令牌。
- **设置**：管理内容目录、转写模型、设备、语言、水印和接口端口。

### 微信读书文章库

文章库由三个区域组成：

- **左栏**：添加公众号、刷新文章、补抓图片、设置自动补齐，以及按公众号查看文章目录。
- **中栏**：只读阅读公众号文章；文章以标签方式打开，单击预览，双击固定标签。文章操作菜单可以打开原文、打开本地 Markdown、固定标签或放到右侧作为参考。
- **右栏**：显示拖入的只读参考文章，不会改变或删除原文章；中栏可以同时打开并编辑 Markdown 创作稿。

抓取逻辑是“公众号独立游标 + 完整翻页 + 幂等去重”：每个公众号单独保存历史游标和同步记录；同步会从游标继续翻页，不受最新文章数量限制；已经存在的文章只记为跳过，不占用本轮新增额度；新正文或内容变化会保存新的快照，旧快照不会被覆盖。

文章库底部状态栏会显示最近一次同步的公众号、发现数量、新增数量、跳过数量、新增快照数量和需关注数量。同步过程中的人工验证、正文读取失败和图片下载失败都会单独提示，不会把已有文章显示成空目录。

### Cliploom 默认内容库

Cliploom 不要求用户自己设计文件夹规则。首次运行会建立：

```text
Documents\Cliploom\
├─ 00-Inbox       待整理的链接、导入文件和临时素材
├─ 01-Raw         原始视频、原始封面、TXT/SRT 和同目录 AI 分析
├─ 02-Wiki        已整理、可长期复用的知识条目
├─ 03-Drafts      正在创作的 Markdown 文案
├─ 04-Published   已确认可发布或已发布的稿件
└─ 99-Archive     归档内容，不参与日常创作
```

视频下载默认写入 `01-Raw\平台\视频名称`。AI 分析文件仍以视频名称开头，并与对应视频保存在同一目录；它不会自动冒充 Wiki，只有用户整理后才进入 `02-Wiki`。设置中可以关闭“按视频整理原始资产”，恢复单层目录。

在视频库左上方切换“知识库”，可以在不增加第五栏的情况下浏览这棵文件树。文件树会定时检查文件是否仍存在；外部删除的文件会显示为“不存在”，不会被软件伪造为空文件。

知识库栏支持按文件名、路径和 Markdown/TXT/SRT 正文搜索；输入至少两个字符后会防抖检索，并显示命中片段和命中类型。搜索时会自动展开匹配文件所在的父目录。

目录展开状态和滚动位置会保存在本机。右键文件夹可以新建子文件夹；右键 Markdown 创作稿可以重命名、移动、归档或恢复到 `03-Drafts`。归档只是移动到 `99-Archive`，同名文件会自动改名，不会覆盖已有文件。

编辑器支持撤销/重做（`Ctrl+Z`、`Ctrl+Shift+Z`、`Ctrl+Y`）。如果同一 Markdown 文件在资源管理器或 Obsidian 中被修改，编辑器干净时会重新加载；有未保存内容时会保留本地编辑并提示外部变更，不会静默覆盖。

编辑器工具栏的“历史”可以查看最近保存的版本正文，并将某个版本恢复为新的当前版本；旧版本不会被覆盖。

转写参考区的时间戳片段可以勾选一条或多条，点击引用图标后会作为 Markdown 引用插入当前创作稿。每个片段都会单独保存视频、转写版本、起止时间和原文来源；编辑器底部的“参考来源”可以查看当前版本、旧文案版本或来源视频已删除等状态。

创作稿中的 `#标签` 会自动建立标签索引；文件开头的 YAML 属性（例如 `status: review`、`priority: 2`、`tags: [教程, AI]`）会建立结构化属性索引。正文仍是唯一事实源，改动后重新保存会同步索引，不会改写正文。

设置中的“立即备份”会生成本地一致性备份，包含视频库数据库、下载队列数据库和配置文件，不包含视频、模型或 API/MCP Token。

每次启动工作台会按日期自动创建一份同样范围的本地快照；已有当天完整快照时不会重复写盘。自动备份会等首屏进入可交互状态后再执行，避免与第一次打开视频库或文章库争抢磁盘；失败不会阻塞使用，但会写入本地日志供排查。

按 `Ctrl+P` 可以打开命令面板，快速切换视频资产/知识库、打开设置、收起面板、刷新内容或创建本地备份。

右侧“插件”面板内置开头钩子、结构模板和发布检查卡片。外部插件放在内容库的 `.cliploom/plugins/<id>/`，目录至少包含 `manifest.json`、`index.html`、`main.js` 和 `styles.css`：

```json
{"id":"my-card","name":"我的卡片","version":"1.0.0","entry":"main.js","styles":"styles.css","html":"index.html"}
```

插件脚本运行在隔离 iframe 中，只能通过 `window.cliploom.getContext()` 读取当前视频/文案摘要，并通过 `window.cliploom.insertText(text)` 请求插入；每次插入都需要用户确认。插件不能访问 SQLite、内容库外路径、API/MCP Token 或网络。Manifest 无效的插件不会加载；停用和移除操作可在插件卡片中完成，移除会进入 `.cliploom/plugin-trash`，不会直接删除。

- Drafts、Wiki 和 Published 下的 Markdown 点击后会进入中间创作区，可继续编辑并保存。
- Raw 下的视频会选中对应视频；TXT/SRT 会切换右侧文案参考；同目录 AI 分析会切换右侧视频解析。

Cliploom 会在 `.cliploom\vault.json` 保存目录规则。这个文件只记录结构说明，不记录视频内容；如果用户误删空的默认目录，下次扫描时会自动恢复目录并在知识库栏提示。

## 3. 下载单条或多条视频

在“视频库”顶部的输入框粘贴链接。支持一个链接、多行批量粘贴、平台分享文本和常见 MP4/WebM/MOV/M3U8 直链。

平台视频由内置的 `yt-dlp` 下载引擎处理，支持 YouTube、Bilibili、Vimeo、X/Twitter、TikTok、Instagram、Facebook、抖音等平台。默认最高 1080p、单并发、禁止自动展开播放列表；需要登录的平台可以在“设置”中选择用户自己导出的 `cookies.txt`。软件不会自动读取浏览器登录态。

微信视频号 `weixin.qq.com/sph/` 分享链接作为实验性能力处理：通过远程解析服务取得视频直链后保存 H.264 版本；该能力依赖第三方服务，服务不可用时只影响当前任务。

加入队列后：

- 下载队列按顺序处理视频。
- 当前视频会显示下载进度。
- 下载成功后自动读取视频时长。
- 开启自动转写时，完成的视频会立即加入转写队列。
- 下载和转写是两条独立队列，可以同时工作。

新下载的 MP4 使用视频标题作为文件名。例如：

```text
3个方法让短视频开头更有吸引力.mp4
```

文件名规则：

- 自动替换 Windows 不允许使用的字符。
- 避免使用 `CON`、`AUX`、`NUL` 等 Windows 保留名称。
- 发现同名文件时追加视频 ID，不覆盖已有文件。
- 旧版本已经下载的文件不会被自动改名，以免破坏已有路径和文案关联。

### 单条下载操作

每条非本地视频下方会根据当前状态显示可用操作：

- **开始下载**：创建或启动该视频的下载任务。
- **暂停下载**：暂停这一条，不影响其他任务。
- **继续下载**：恢复已暂停的任务。
- **重试下载**：重新处理失败任务。
- **重新下载**：文件丢失或需要重新获取时使用。

顶部“暂停队列”会暂停整个下载队列；单条“暂停下载”只作用于当前视频。

## 4. 抓取博主主页

打开左侧“主页抓取”：

1. 粘贴抖音博主主页链接。
2. 勾选授权声明。
3. 点击“开始抓取”。
4. 软件弹出浏览器后，在浏览器中登录抖音。
5. 登录完成后回到工作台，点击“我已登录”。
6. 等待软件滚动并收集视频。
7. 在结果列表中勾选需要的视频，也可以全选。
8. 将所选视频加入下载队列。

注意事项：

- 抖音登录只用于主页抓取，不是软件账号或激活。
- 如果出现验证码，请在弹出的浏览器完成验证，再点击“已完成验证，继续”。
- 可以随时点击“中止抓取”。已经找到的视频不会因此自动下载，需要在结果列表中确认加入。
- 是否保留水印由“设置”中的选项决定。

## 5. 文件/文件夹批量转写

打开左侧“批量转写”，可以选择单个文件、多选文件或整个文件夹。选择文件夹时会递归查找视频和音频文件，支持 MP4、MOV、MKV、AVI、WebM、MP3、WAV、FLAC、M4A 等常见格式。

选择后软件会先扫描，不会立刻启动任务。确认摘要后点击“开始转写”：

```text
找到文件：86
待转写：52
已有文案：31
已在视频库：20
```

默认勾选“跳过已有有效 TXT/SRT”，与原转写器保持一致。扫描结果会显示前 20 个文件，完整批次会保存到视频库和批次记录中。

执行时会沿用原转写器的行为：

1. 逐个处理文件并显示当前文件和百分比。
2. 单个文件失败不会阻塞后面的文件。
3. 可以停止当前批次，已完成文件不会被覆盖。
4. TXT/SRT 默认写入源视频或音频所在目录。
5. 同一个文件按 SHA-256 去重，重复文件不会创建第二份视频资产。

## 6. 搜索、筛选和批量操作

视频库支持按标题、作者或链接搜索，并可按来源、转写状态和 AI 状态筛选。

中间列表可以持续滚动。每次加载 100 条，接近底部时会继续加载，因此视频数量较多时也能浏览后面的内容。

### 选择视频

- 勾选每条视频前面的复选框，可以部分选择。
- 勾选表头复选框，选择当前已经加载到列表中的视频。
- 已经选择部分视频后，可点击“选择全部 N 条”，选择当前搜索和筛选条件下的全部结果。
- 修改搜索词或筛选条件时，原选择会清空，避免对错误范围执行批量操作。

### 批量动作

选中视频后，下载和转写动作由列表表头对应栏位的按钮控制：

```text
视频             时长       下载 [开始/停止]       转写 [开始/停止]       AI
```

每个视频行的下载栏和转写栏同时显示状态与一个动作按钮。表头按钮控制当前范围的任务；如果勾选了视频，则控制已选视频，否则控制当前筛选结果。

单行按钮也使用同一逻辑：等待或失败时显示“开始”，运行时显示“停止”，已完成时显示“重新下载”或“重新转写”。

批量动作的含义：

| 操作 | 行为 |
| --- | --- |
| 下载栏“开始/停止” | 开始等待、暂停、失败或已停止的下载；停止下载会暂停任务，之后可以继续 |
| 转写栏“开始/停止” | 开始已就绪文件的转写；停止等待任务或安全停止当前转写 |
| 删除 | 删除所选任务和资产，可选择同时移入回收站 |

批量操作完成后会分别显示成功、跳过和失败数量。部分视频条件不满足时只会跳过对应视频，不会阻塞其他视频。

### 历史视频数据

升级后的首次启动会把历史抖音视频安全标记为“抖音”，但不会虚构播放量、点赞量等平台指标。平台指标需要重新访问原始抖音链接采集。

- 点击视频行里的“刷新数据”，只刷新当前视频的平台详情，不重新下载视频，也不重新转写。
- 勾选部分视频后，点击批量操作区的“刷新视频数据”，只处理选中项。
- 未选择视频时，点击视频库右上角“刷新视频数据”，处理当前搜索/筛选范围。
- 刷新过程会显示当前进度；完成后汇总成功、跳过和失败数量。
- 每次成功刷新都会保存一条带采集时间的数据快照，历史快照不会被覆盖。
- 本地文件、没有原始抖音链接、视频已删除或页面无法访问的项目会被跳过或标记失败，不会生成空数据。

## 7. 自动转写和手动转写

### 自动转写

“自动转写”只负责在视频下载或导入完成时自动排队。它不会禁止手动操作。

- 第一条视频下载完成后就可以开始转写。
- 不需要等待所有视频下载完成。
- 下载队列和转写队列各自单并发运行，防止显存或内存被多个任务同时占满。

如果不希望所有新视频自动转写，可以在“设置”中关闭“自动转写”。关闭后仍可对任意文件手动点击“转写”。

### 手动操作

- **转写**：将未转写、失败或已停止的视频加入队列。
- **优先转写**：把等待中的视频提高优先级，让它先于普通自动任务处理。
- **停止转写**：等待当前模型推理到安全边界后停止，避免产生损坏的半成品文件。
- **重新转写**：产生一个新的文案版本，不覆盖历史文案。

如果任务显示“等待转写”，通常表示前面还有其他转写任务。可以点击该视频的“优先转写”，也可以勾选多条后使用批量“优先转写”。

### 模型和设备

设置中可选择：

- 模型：`small`、`medium`、`large-v3`。
- 设备：自动、NVIDIA GPU、CPU。
- 语言：自动检测、中文、英文。
- 中文输出：简体中文或繁体中文。
- VAD：静音分段、语音填充和检测灵敏度。

默认推荐 `medium + 自动设备 + 自动检测`。GPU 不可用或显存不足时，软件会自动回退到 CPU。

首次真正需要某个本机没有的模型时，软件会显示模型下载提示。模型较大，下载和首次加载可能需要一些时间。

## 8. 查看视频详情、文案和分析

点击视频后，右侧详情栏包含三个页签。

### 概览

显示来源、时长、文件大小、下载状态、转写状态和处理轨迹。视频文件存在时可以点击“在文件夹中显示”。

### 文案

- 切换不可覆盖的历史文案版本。
- 查看语言、简繁版本、模型、分段数和生成时间。
- 复制完整文案。
- 导出 TXT。
- 优先、停止或重新开始转写。

### AI 分析

- 查看外部 AI 写回的 Markdown 分析。
- 在多个分析版本之间切换。
- 复制分析内容。
- 导出 Markdown。
- 新文案产生后，旧分析仍会保留，但会标记为“基于旧文案”。

软件不内置大模型，也不会伪装成已经自动分析。没有连接外部 AI 时，AI 状态会正常显示“待 AI 分析”。

## 9. MCP 接口使用

内容服务默认监听：

```text
MCP：http://127.0.0.1:8765/mcp
REST：http://127.0.0.1:8765/api/v1
健康检查：http://127.0.0.1:8765/health
```

实际地址以“接口中心”显示为准。修改接口端口后，需要保存设置并重启软件。

### 连接外部 AI

在“接口中心”点击“复制完整配置”。复制内容包含：

- Streamable HTTP 传输方式。
- 当前 MCP 地址。
- `Authorization: Bearer <访问令牌>` 请求头。

将它粘贴到支持 MCP Streamable HTTP 的 AI 客户端配置中。连接成功后，AI 可以使用以下能力：

| MCP 能力 | 用途 |
| --- | --- |
| `get_work_rules` | 获取所有 AI 必须遵守的分析规则 |
| `list_videos` | 搜索或筛选视频资产 |
| `get_video_context` | 获取视频元数据、任务状态和当前文案信息 |
| `get_transcript` | 获取当前或历史文案全文 |
| `list_analyses` | 查看全部 AI 分析版本 |
| `save_analysis` | 将 Markdown 分析写回指定文案版本 |
| `set_current_analysis` | 将某个历史分析设为当前版本 |
| `analyze_video_copy` | 获取一份标准视频文案分析提示模板 |

AI 只能读取视频文案并写回分析，不能通过 MCP 下载或删除视频。

### 推荐 AI 工作流

```text
get_work_rules
    ↓
list_videos
    ↓
get_video_context / get_transcript
    ↓
AI 分析文案
    ↓
save_analysis
    ↓
工作台右侧显示分析
```

`save_analysis` 必须使用真实的 `video_id` 和 `transcript_id`。分析基于哪个文案版本会被永久记录，重新转写不会覆盖旧分析。

每次分析还会自动生成一个 Markdown 文件：文件名以视频名称开头，保存在视频文件同一目录，并同步显示在软件右侧“AI 分析”页。分析正文首个标题也会自动补上视频名称；外部 AI 不应只在聊天窗口输出结果。

### 访问令牌

- 令牌默认遮罩显示，可以手动显示或复制。
- 不要把令牌发送给不可信的人或写入公开文件。
- 点击“重新生成”后，旧令牌立即失效，所有已连接的 AI 客户端都需要更新配置。
- 服务仅绑定 `127.0.0.1`，不会向局域网或互联网开放。

## 10. REST API

除健康检查外，所有接口都需要请求头：

```text
Authorization: Bearer <接口中心显示的访问令牌>
```

主要接口：

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/health` | 检查本地服务是否正常 |
| GET | `/api/v1/videos` | 分页、搜索和筛选视频 |
| GET | `/api/v1/work-rules` | 获取 AI 分析工作规则和推荐调用顺序 |
| GET | `/api/v1/videos/{id}/context` | 获取视频上下文 |
| GET | `/api/v1/videos/{id}/transcript` | 获取当前或指定版本文案 |
| GET | `/api/v1/videos/{id}/analyses` | 获取分析历史 |
| POST | `/api/v1/videos/{id}/analyses` | 保存新的 Markdown 分析 |
| PATCH | `/api/v1/videos/{id}/analyses/{analysisId}/current` | 设置当前分析版本 |

视频列表支持 `query`、`source_type`、`transcription_status`、`analysis_status`、`limit` 和 `cursor` 参数。

## 11. 删除、文件和数据安全

### 删除一条视频

点击视频下方“删除”后，可以选择：

- **仅删除任务**：从工作台删除视频资产、任务、文案和分析记录，但保留磁盘文件。
- **删除任务和文件**：先停止相关下载和转写，再将视频、TXT 和 SRT 移入 Windows 回收站。

### 批量删除

勾选多条视频后点击“删除”，软件会逐条安全处理。某条失败不会中断其他条目，完成后会显示汇总。

删除规则：

- 文件使用 Windows 回收站，通常可以恢复。
- 数据库中的视频、任务、文案和分析关联会同步清理。
- 原导入或下载批次的统计与审计记录会保留，但不再指向已删除视频。
- 如果转写仍在安全停止，软件会暂缓删除并提示稍后重试。
- 如果文件在软件外被手动删除，视频库会显示“文件丢失”。

### 数据保存位置

- 视频、TXT、SRT：保存在“设置”选择的内容目录。
- SQLite 数据库、接口令牌和应用配置：保存在 Electron 的 Windows `userData` 目录。
- 主页抓取的浏览器登录数据：保存在下载 sidecar 的本地浏览器数据目录。

软件重启后，视频资产、任务、文案和分析历史不会丢失。上次意外中断的转写任务会恢复为等待状态。

## 12. 状态说明

### 下载状态

| 状态 | 含义 |
| --- | --- |
| 本地文件 | 不需要下载 |
| 等待下载 | 已进入下载队列 |
| 解析中 | 正在解析抖音页面和视频地址 |
| 下载中 | 正在保存视频文件 |
| 已暂停 | 该任务已暂停，可继续 |
| 已就绪 | 文件已经可以使用 |
| 下载失败 | 可查看错误并重试 |
| 已停止 | 任务已取消，可重新开始 |
| 文件丢失 | 数据库有记录，但磁盘文件不存在 |

### 转写状态

| 状态 | 含义 |
| --- | --- |
| 未转写 | 尚未加入转写队列 |
| 等待转写 | 正在等待前面的任务 |
| 加载模型 | 正在读取或下载 Whisper 模型 |
| 转写中 | 正在生成文案 |
| 文案就绪 | 已生成至少一个文案版本 |
| 转写失败 | 可以重新转写 |
| 已停止 | 已取消等待或安全停止 |

### AI 状态

| 状态 | 含义 |
| --- | --- |
| 待 AI 分析 | 尚无外部 AI 写回结果 |
| 分析就绪 | 当前文案已有当前分析 |
| 分析已过期 | 当前分析基于旧文案版本 |

## 13. 常见问题

### 双击启动文件后没有启动

请在项目目录打开 PowerShell，运行：

```powershell
npm run dev
```

根据错误信息检查：

- 项目目录是否存在 `node_modules`。
- 电脑是否安装 Node.js。
- 项目根目录的 `.venv/Scripts/python.exe` 是否存在。
- 软件或本地接口是否已经在另一个窗口运行。

启动脚本失败时会保留命令行窗口。请不要立即关闭，把窗口中的完整错误信息用于排查。

### 为什么一直显示“等待转写”

转写队列按顺序单任务运行。确认视频文件已经就绪，然后点击该视频的“优先转写”。这不会影响自动转写设置，也不需要等待所有视频下载完成。

### 为什么软件还要下载模型

工作台只会复用与当前选择完全匹配的模型。如果原工具缓存的是 `medium`，但设置中选择了 `large-v3`，软件仍需要下载 `large-v3`。在设置中查看“已检测到本机模型缓存”的提示。

### GPU 不能使用怎么办

设备选择“自动”。GPU 不可用或显存不足时会回退 CPU。CPU 转写速度会更慢，但不会影响文案版本和输出文件。

### 为什么 AI 分析没有自动出现

软件不内置 AI 模型。必须在“接口中心”将 MCP 配置连接到 Codex、Claude 或其他客户端，并让 AI 调用 `save_analysis` 写回结果。

### 为什么 AI 接口连接失败

依次检查：

1. 软件是否仍在运行。
2. “接口中心”是否显示本地服务运行中。
3. 客户端地址是否与当前端口一致。
4. 请求头是否包含完整 Bearer Token。
5. 是否重置过令牌但没有更新客户端配置。

### 为什么主页抓取停止了

可能是未登录、触发验证码或网页状态变化。回到弹出的浏览器完成登录或验证，再点击继续。如果仍失败，关闭抓取浏览器后重新开始当前博主。

### 删除任务后文件还在吗

取决于删除弹窗中的选择：

- 勾选“同时删除本地文件”：文件移入回收站。
- 不勾选：只清理工作台记录，文件保留。

## 14. 首次配置开发环境

已经可以通过 BAT 正常启动的电脑不需要重复执行本节。

推荐环境：Node.js 20+、pnpm 9+、Python 3.11–3.13。

在项目目录执行：

```powershell
pnpm install

python -m venv apps/sidecar/.venv
apps/sidecar/.venv/Scripts/python.exe -m pip install -r apps/sidecar/requirements.txt
apps/sidecar/.venv/Scripts/python.exe -m playwright install chromium

python -m venv .venv
.venv/Scripts/python.exe -m pip install -r apps/content-sidecar/requirements.txt
```

内容服务只使用当前项目根目录 `.venv`。开发版可以复用项目根目录 `models/<模型名>`；安装包不携带模型，首次选择本机没有的模型时会按提示下载到当前用户缓存。

首次升级会幂等读取 `%APPDATA%/transcribe/settings.json`，迁移模型、设备、语言、简繁和 VAD 设置。原设置文件保持不变。
